## 2. 시스템 지형 — 정산이 어떻게 굴러가나

- 시스템: **NetEase OA** → `差旅报销`(차뤼바오샤오, 출장비 정산). 업로드 파이프라인은 사내 워크플로 엔진 **easeflow(易流)**.
- **정산서(报销单) 1건 = 출장 1건.** 제목 형식 `差旅报销-{영문 이름}-{날짜}`.
- 정산서 하나 안에 **탭 4개가 공존**한다: `机票、火车票`(항공권·기차표) / `酒店费用`(호텔) / `个人餐费`(식비) / `交通费`(교통비). 탭마다 엑셀을 따로 올린다(`Bulk Import`).
- **사용자는 출장 건마다 정산을 올린다** (2026-08-18 확인). 월말 몰아서가 아니다.
- 옆에 `业务招待费`(업무 접대비)·`团建费`(팀빌딩비) 추가 버튼이 따로 있다 → **다른 비용 유형은 별도 템플릿.**

## 3. 확정된 결정 (5건)

### D1. 레포에는 스킬 로직·문서만 커밋한다
이 레포는 **PUBLIC이고 소유자가 타인**이다. 그래서:
- **커밋함**: 스킬 코드, 이 문서들 (템플릿 구조·컬럼명 수준)
- **커밋 안 함**: 템플릿 원본 `.xlsx`, 영수증 이미지, 채워진 결과물, 숨김 시트 토큰 값, 동료 실명
- 근거: 컬럼 구조는 스킬이 돌려면 어차피 문서화돼야 하고 민감도가 낮다. 반면 **개인 이름·금액·사내 토큰이 박힌 실제 파일은 공개될 이유가 없다.**

### D2. 템플릿은 **재사용**한다 (매번 새로 받지 않는다)
- 업로드할 양식은 회사가 고정해뒀으니 **한 번 받은 걸 복사해서 계속 쓴다.** 매번 4번 다운로드는 낭비.
- **단 안전망**: 원본 4개는 **마스터로 봉인**해두고 절대 건드리지 않는다. 출장 폴더마다 마스터를 **복사**해서 그 복사본에 행을 쌓는다.
- 파일명은 바꿔도 되지만 **원본 접두어(`差旅报销_机票、火车票_`)는 남긴다** — 서버가 파일명을 검사하는지 미확인이라.
- **미검증 위험**: 숨김 시트 토큰이 다운로드마다 발급되는 1회용일 가능성이 남아 있다. 첫 업로드가 튕기면 그때 새로 받으면 되고, 그 결과로 재사용 가능 여부가 판별된다.

### D3. 폴더 하나 = 출장 1건 *(2026-08-18 개정 — 사용자의 실제 컨벤션을 채택)*
- **폴더명 = `{IATA 공항코드}-{YYYYMM}`.** 예: `TPE-202608`(타이베이 2026년 8월), `HKF-202608`(홍콩).
- ⚠️ **이건 내가 정한 게 아니라 사용자가 이미 쓰고 있던 규칙이다.** 처음엔 `20260818-항저우` 같은 날짜+한글 지명을 제안했으나, 사용자 바탕화면의 기존 폴더를 발견하고 그쪽으로 통일했다. **우리 컨벤션을 사용자에게 강요하지 않는다.**
- 폴더 = 정산서 1건 = 업로드 단위.
- **왜 지역·나라 축이 아닌가**: 지역명은 폴더명에 이미 들어가서 정렬·검색이 되고, 무엇보다 출장 단위여야 `是否国际`(국제출장 여부)·`国际出差地区`(국제 출장 지역)·`币种`(통화)·출장자 같은 **반복값이 폴더 전체에서 고정**된다. 나라별 폴더는 국내·해외가 섞여 그 이점이 사라진다.
- 나중에 `2026/중국/20260818-항저우/`처럼 위에 축을 덧씌우는 건 폴더 이동만 하면 된다. 분기 기준은 계속 디벨롭한다.

### D4. `币种`(통화) 표기는 `코드-중국어명` 형식
화면 드롭다운 실측 결과 `CNY-人民币` 형식이었다(`CNY`가 아니다). 전체 목록은 → [expense-templates.md §4](./expense-templates.md)
- **미확정**: 엑셀에 전체 문자열(`CNY-人民币`)을 넣을지 코드만(`CNY`) 넣을지. 첫 업로드로 검증.

### D5. 산출물은 엑셀뿐 (§1 범위 표)

### D13. **완성된 엑셀은 사용자의 `expenses` 폴더에도 저장한다** *(2026-08-18 — 사용자 지시. ⚠️ 2026-08-31 D20으로 개정: 이중 저장 폐기, 경로 변경)*
> ~~`C:\Users\admin\OneDrive\Desktop\expenses\{IATA}-{YYYYMM}\`~~ → **`music/expenses/{지역}-{YYYYMM}/`** (D20)

사용자 지시: *"앞으로 엑셀 파일을 `expenses` 폴더에 별도로 저장해줘"*. 레포(`data/expense/`) 저장은 그대로 두고 **거기에 더해** 사용자 작업 폴더에도 사본을 둔다.
- **왜 두 곳인가**: 레포 쪽은 재현·이력용(gitignore되지만 다른 산출물과 함께 있다), `expenses` 쪽은 **사용자가 실제로 열어서 업로드하는 곳**이다. 사용자가 레포 경로를 뒤지게 만들지 않는다.
- **파일명**: `差旅报销_{항목}_{IATA}-{YYMM}.xlsx` — 예: **`差旅报销_个人餐费_TPE-2608.xlsx`** *(2026-08-18 사용자 지시로 확정)*. 원본 접두어 `差旅报销_`은 유지한다(D2).
- ⚠️ **폴더는 6자리(`TPE-202608`), 파일은 4자리(`TPE-2608`)** 다. 헷갈리지만 사용자가 지정한 형태이므로 그대로 쓴다.
- **위치**: 출장 폴더 **최상위**. 하위 `flight`·`food`·`hotel`·`transportation`·`telecom`은 **영수증 원본(입력)** 자리이고, 엑셀은 **산출물**이라 섞지 않는다.

#### 사용자의 기존 폴더 구조 *(2026-08-18 실측 — 우리가 만든 게 아니다)*
```
expenses/
├─ TPE-202608/            ← 타이베이 (이번 건)
│  ├─ flight/             E-receipt_Taipei.pdf
│  ├─ food/               영수증 사진 12장
│  ├─ telecom/            전자영수증.pdf  → 「기타」 몫 (D8)
│  ├─ transportation/     PDF 2건
│  └─ 差旅报销_个人餐费_TPE-202608.xlsx   ← 우리 산출물
└─ HKF-202608/            ← 홍콩 (미처리)
   ├─ flight/  food/  hotel/  transportation/
```
- **카테고리 폴더명이 곧 템플릿 매핑**이다: `flight`→`机票、火车票`, `hotel`→`酒店费用`, `food`→`个人餐费`, `transportation`→`交通费`, `telecom`→미분류 버킷(D6).
- **`hotel` 폴더는 출장마다 있을 수도 없을 수도 있다** — TPE엔 없고 HKF엔 있다. 없으면 그 템플릿은 만들지 않는다.

### D6. 영수증 → 파일 분류표 확정 + **「미분류 버킷」** *(2026-08-18, 질문 7 종결)*
분류표는 §5 확정본을 쓴다. 그리고 **4종 어디에도 확실히 안 맞는 영수증은 자동 분류하지 않는다.**
- `unclassified`(미분류) 목록으로 빼서 **"이건 제가 못 넣습니다 — 어디로 갈지 알려주세요"** 라고 사용자에게 되묻는다.
- **왜 예외 처리가 아니라 일반 규칙인가**: 물품 구매만 예외로 두면 비자비·로밍비가 나왔을 때 똑같이 막힌다. 버킷 하나로 전부 받는다.
- **왜 억지로 안 넣나**: 물품비를 `交通费`(교통비)에 밀어넣으면 임포트는 통과해도 **엉뚱한 비용 항목으로 정산된다.** 회계 문서에서 제일 나쁜 실패다. (핵심원칙 3 — 모르는 값을 지어내지 않는다)

### D7. 항공권의 `交通工具`(교통수단)는 **무조건 `飞机经济舱`(비행기 이코노미석)** *(2026-08-18 — 사용자 지시)*
`机票、火车票` 파일 **G열 `交通工具`**. 영수증의 예약 클래스(Y/J/F)를 읽어 매핑하지 **않는다.** 항공권이면 무조건 이 값 하나다.
- 즉 이 칸은 ②유도가 아니라 **고정값**이다. 판독 로직이 필요 없다.
- **기차표는 다르다** — 좌석 등급이 표에 인쇄되므로 ①직독으로 그대로 옮긴다 (`高铁二等座` 등, 드롭다운 6종 → [expense-templates.md §3-1](./expense-templates.md)).
- ⚠️ 남은 틈: `动车`(D열차, 둥처)는 드롭다운 6종에 없다. 실제로 탈 일이 생기면 `火车`(일반 기차)로 넣을지 확인 필요.

### D8. 「기타」 비용은 **별도 템플릿이 따로 있다** → v1 범위 밖 *(2026-08-18 — 사용자 지시)*
개인 물품 구매·로밍 요금 등은 **이 4종에 표기하지 않는다.** 회사에 **「기타」 항목을 채우는 템플릿이 별도로 존재**한다(사용자 확인). 화면에 `业务招待费`(업무 접대비)·`团建费`(팀빌딩비) 버튼이 따로 있는 것과 같은 결이다.
- v1은 **그 템플릿을 손에 넣기 전까지 설계하지 않는다** (YAGNI). D6의 미분류 버킷으로 빼서 사용자에게 넘긴다.
- 필요해지면 그때 템플릿을 받아 5번째 파일로 붙인다.

### D9. **식음료를 파는 곳의 영수증은 전부 `个人餐费`(식비)** *(2026-08-18 — 사용자 지시)*
편의점(7-ELEVEN 등)·포장식품점(`新东阳` 신동양)처럼 "먹은 건지 산 건지" 애매한 곳도 **모두 식비**로 넣는다. 물품으로 빼지 않는다.
- 사용자 원문: *"7 ELEVEN은 **모두** 식비/음료로 표기"* — 이번 1건에 대한 판정이 아니라 **규칙**으로 적용한다.
- **경계선**: 식음료를 파는 업태면 식비. 약국·면세점·잡화처럼 식음료가 아닌 곳은 D6의 미분류 버킷.
- **`详细说明`에 끼니를 추정해 쓰지 않는다.** 영수증에 `早餐`(조식)·`午餐`(중식) 구분이 찍히지 않으므로, 결제 시각으로 끼니를 짐작하는 대신 **`餐饮`(식음료)** 로 적는다. (핵심원칙 3 — 모르는 값을 지어내지 않는다)

### D10. 사람 이름 칸은 **엑셀에서 비워둔다** *(2026-08-18 개정 — 사용자 지시, 열린 질문 10 종결)*
`个人餐费` G열 `就餐人`(같이 식사한 사람), `酒店费用` G열 `同住人`(같이 묵은 사람) 등 이름 칸은 **채우지 않고 빈 칸으로 남긴다.**
- 사용자 원문: *"내 이름이 적힌 항목은 그냥 비워둬. 올리는 플랫폼에 내가 직접 클릭으로 채워넣어야 해."* → 화면에 **사람 검색·선택 위젯**이 있어서, 자유 텍스트로 이름을 써 넣는 것보다 거기서 고르는 게 정확하다.
- **빈 칸 = 셀을 아예 만들지 않는다.** 빈 문자열(`<t></t>`)이 든 셀과 셀이 없는 것은 파서에 따라 다르게 취급될 수 있어, 후자로 맞춘다.
- ⚠️ 헤더가 `*就餐人`으로 **필수 표시**라 임포트가 튕길 여지가 있다. 튕기면 그때 채운다 — 되돌리기 쉬운 쪽을 먼저 시도한다.
- `就餐人数`(식사 인원 수)는 **그대로 `1`을 넣는다.** 이름 칸이 아니라 숫자 칸이고, 사용자가 *"대부분 1인"* 이라 확인했다.

### D17. **국제출장 판정은 「출장」이 아니라 「비용이 발생한 나라」 단위다** *(2026-08-31 — 사용자 설명 + 서버 로그 실증. D12·D16 대체)*

> **한국에서 쓴 돈은 `是`(예) + `国际出差地区`=`韩国`. 중국 본토에서 쓴 돈은 `否`(아니오) + 지역 비움.**

사용자 설명 원문: *"나는 주로 한국에서 출장을 시작해. 아무리 중국으로 가는 일정이어도 출발하는 나라가 한국이기 때문에 출발시 무조건 「국제출장지역」으로 표기하게 되어 있어. 하지만 중국 현지에 도착한 다음에 발생하는 비용은 모두 국제출장이 아닌 것으로 표기가 되어 있어야 해."*

**왜 이렇게 되나**: 회사는 중국 법인이고 사용자는 한국 근무다. 회계 기준이 **회사 소재국(중국)** 이므로 —

| 비용이 발생한 곳 | `是否国际/港澳台出差` | `国际出差地区` |
|---|---|---|
| 🇰🇷 한국 (출국 전·귀국 후 공항 포함) | `是` | `韩国` |
| 🇨🇳 중국 본토 | `否` | **(비움)** ← 미검증 |
| 🇹🇼 대만 · 🇭🇰 홍콩 · 🇲🇴 마카오 | `是` | `台湾` / (홍콩·마카오는 목록 확인 필요) |
| 그 외 해외 | `是` | 마스터 목록의 해당 국가명 |

- **판정 근거는 통화가 아니라 「가게 위치」다.** KRW/CNY가 대체로 일치하지만 예외가 있을 수 있다. 영수증의 상호·주소로 나라를 판정하고, 애매하면 묻는다.
- **`交通费`(교통비) 파일엔 이 열이 아예 없다** → 해당 없음.
- ⚠️ **미검증 1건**: 중국 본토 행의 `国际出差地区`를 **비우는 것**이 통하는지. `中国`·`烟台市` 둘 다 거부됐으니 남은 후보가 이것뿐이다. `就餐人`·`是否国际`가 빈칸으로 통과한 전례가 있어 가능성은 높다.
### D17-1. **`是否国际`는 층위가 둘이다 — 「출장 신청서」 값과 「정산 행」 값을 혼동하지 않는다** *(2026-08-31 — 사용자 설명, 모순 관측 해소)*

화면 `公司行政预定信息`(회사 행정 예약 정보)에 회사가 예약한 **중국 국내선(베이징→상하이)** 이 `是否国际/港澳台出差`=`是`로 찍혀 있었다. D17(중국 본토 = `否`)과 정면으로 어긋나 보였지만 **모순이 아니다.**

사용자 설명: *"출장 허가 신청서를 올릴 때 내가 한국에서 출발하는 것, 그리고 출장 도중에 북경에서 상해로 이동하는 일정이라, 시스템상의 문제라고 알고 있으면 돼."*

| 층위 | 값을 정하는 기준 | 예 (한국 출발 → 베이징 → 상하이) |
|---|---|---|
| **출장 허가 신청서 (`出差申请`)** | **출장 전체**가 한국 출발이므로 `是` | 신청서 전체 = `是`. 그 아래 구간(베이징→상하이)도 상속받아 `是`로 표시됨 |
| **정산 명세 행 (`报销项目明细`)** | **그 비용이 발생한 나라** (D17) | 한국 지출 `是`+`韩国` / 중국 본토 지출 `否`+비움 |

- **회사 행정 예약 패널의 `是`는 신청서 층위의 값**이고, 우리가 엑셀에 채우는 건 **정산 행 층위**다. 서로 다른 칸이다.
- **그 패널 값을 보고 엑셀 값을 정하지 않는다.** 판정 기준은 언제나 D17(비용 발생국)이다.
- 덧붙여 `公司行政预定信息`에 잡힌 건 **회사가 직접 예약·결제한 건**(`行政预定-机票/火车票`·`行政预定-酒店费用`)이라, 애초에 개인 정산 대상이 아닐 수 있다. 9월 건 정산 시 이 구분부터 확인한다.
- 기존 `TPE-202608` 산출물은 9행 전부 `Taiwan`으로 채워져 있다 → **D17 기준으로는 김포공항 건만 `韩国`이어야 한다.** 재업로드 전 수정 필요.

## 3-1. 영수증 PDF에서 글자를 꺼내는 법 *(2026-08-18 실측)*

이 PC엔 파이썬도 poppler도 없다. 그래도 PDF는 읽힌다 — **유형에 따라 방법이 다르다.**

| PDF 유형 | 방법 | 결과 |
|---|---|---|
| 영문 위주 (예: Trip.com 항공권) | **Word COM** — `Documents.Open` → `SaveAs2(path, 7)`(=`wdFormatUnicodeText`) | ✅ 그대로 읽힘 |
| **한글 + CID 서브셋 폰트** (예: 카카오페이 거래확인증) | Word·Edge 헤드리스 **둘 다 실패** → `?`만 나오거나 백지 | ❌ |
| 위와 같은 PDF | **`/ToUnicode` CMap을 직접 파싱** → 스크래치패드의 `pdftext.ps1` | ✅ 전문 복원 |

**왜 Word가 실패하나**: 폰트가 `Identity-H` CID 서브셋(`ADJLLE+AppleSDGothicNeoR00`)이라 글리프 번호가 유니코드와 무관하다. 변환기가 매핑을 포기하면 전부 `?`가 된다. 하지만 PDF 안에 **`/ToUnicode` CMap이 같이 들어 있어서** 그걸 읽으면 복원된다.

**`pdftext.ps1`이 하는 일** — ① 모든 스트림을 inflate ② `beginbfchar`/`beginbfrange`로 CID→유니코드 표 구성 ③ 본문의 `Tj`/`TJ` 피연산자를 2바이트씩 끊어 변환.

**함정 2개 (같은 실수 반복 금지)**
1. **`New-Object System.IO.MemoryStream($bytes, $off, $len)` 는 동작하지 않는다.** PowerShell이 `byte[]`를 인자 배열로 펼쳐버린다. → **`[System.IO.MemoryStream]::new(...)`** 를 쓴다.
2. **`DeflateStream`은 스트림 끝에서 예외를 던진다** (deflate 데이터 뒤 `endstream` 앞의 잔여 바이트 때문). 예외를 잡되 **그때까지 읽은 바이트는 버리지 않는다.**
3. 숫자·금액은 `<hex>`가 아니라 **리터럴 `(...)` 문자열**로 그려질 수 있다(PDFium 산출물). 8진 이스케이프까지 처리해야 금액이 나온다.

**Edge 헤드리스 스크린샷은 안 된다** — `--headless=new --screenshot`으로 PDF를 열면 뷰어 플러그인이 없어 **백지 PNG**가 나온다. 시도하지 말 것.

### 2026-08-24 추가 — **막히면 렌더링해서 눈으로 읽는다**

위 3가지로도 안 되는 PDF가 있었다. 그래서 표를 이렇게 확장한다.

| PDF 유형 | 방법 | 결과 |
|---|---|---|
| **`ToUnicode`가 「항등 CMap」인 PDF** (Trip.com 호텔 영수증, `微信支付电子凭证` 위챗 전자증빙) | `pdftext.ps1`도 **실패** | ❌ |
| 위와 같은 PDF · **이미지만 든 PDF** (사진·스캔) | **`tools/pdfrender.ps1` — Windows 내장 PDF 래스터라이저로 PNG 렌더 후 읽기** | ✅ **유형 불문 항상 됨** |
| 텍스트가 정상인 PDF (Trip.com 항공권 영문판 등) | **`pdftotext`** — Git for Windows에 `/mingw64/bin/pdftotext.exe`로 **이미 깔려 있다** | ✅ Word COM보다 간단 |

**왜 `pdftext.ps1`이 실패하나**: 이 PDF들의 `/ToUnicode` 스트림은 실제 매핑이 아니라 `1 begincidrange <0000> <FFFF> 0 endcidrange` — **항등 사상**이다. 코드→CID만 말해줄 뿐 **유니코드 정보가 아예 없다.** poppler도 `Invalid 'begincidrange' operator in ToUnicode CMap` 경고를 내고 한자를 통째로 버린다. 파싱으로 뚫을 수 있는 문제가 아니다.

**`tools/pdfrender.ps1`** — Windows 10/11이 WinRT에 **PDF 래스터라이저(`Windows.Data.Pdf.PdfDocument`)를 내장**하고 있다. poppler·파이썬·pdftoppm 없이 PowerShell에서 바로 부를 수 있다.
```powershell
tools/pdfrender.ps1 -Pdf <파일.pdf> -OutDir <폴더> [-Width 1600] [-Pages "1,2"]
```
- 페이지당 PNG 1장. `-Width`로 해상도 조절(작은 글씨는 2000 이상 권장).
- **함정**: PowerShell 5.1에서 WinRT async를 기다리려면 `AsTask` 오버로드를 **`IAsyncOperation<T>`용과 `IAsyncAction`용으로 따로** 골라야 한다. 스크립트 상단에 그 처리가 들어 있다.
- **이 도구 덕분에 「못 읽는 PDF」는 사실상 없어졌다.** 텍스트 추출이 막히면 곧장 렌더링으로 간다.

**`tools/pdfsplit.ps1`** — PDFium이 만든 「한 페이지 = 전면 이미지 1장」 PDF를 페이지별 PDF로 쪼갠다(카카오톡으로 받은 영수증 묶음이 이 형태다). 이미지 스트림을 **재인코딩 없이 바이트 그대로** 복사하므로 화질 손실이 없다.
```powershell
tools/pdfsplit.ps1 -Pdf <묶음.pdf> -Map <csv: 페이지번호,출력경로> -OutRoot <폴더>
```

## 4. 값의 출처는 세 등급이다

"채울 수 있다/없다"의 문제가 아니라 **값이 어디서 오느냐**의 문제다.

| 등급 | 뜻 | 처리 |
|---|---|---|
| ① **직독** | 영수증 지면에 값이 그대로 있음 | 읽어서 넣는다 |
| ② **유도** | 지면엔 없지만 다른 값에서 확정됨 (예: 출발·도착지 → 국제출장 여부) | **규칙을 합의하면 자동** |
| ③ **영수증 밖** | 지면 어디에도 근거가 없음. 사람 머릿속에 있음 | **사용자가 줘야 한다** |

### 잠정 등급표 (⚠️ 영수증 실물 미확인 — 샘플 받으면 실측으로 교체)

| 파일 | ① 직독 | ② 유도 | ③ 영수증 밖 |
|---|---|---|---|
| `机票、火车票` | 날짜·통화·금액·`出发地点`·`抵达地点`, **기차표의 `交通工具`**(좌석 등급이 표에 인쇄됨) | `是否国际` / **항공권의 `交通工具`는 판독 불필요 — 고정값 `飞机经济舱`** (D7) | `详细说明` |
| `酒店费用` | `入住日期`·`离店日期`·통화·금액 | `是否国际`(호텔 주소) | `同住人`, `详细说明`, (`住宿人数`는 인보이스에 찍히면 ①) |
| `个人餐费` | 날짜·통화·금액 | `是否国际`·`国际出差地区`(상호 주소), `就餐天数` | **`就餐人数`**, **`就餐人`**, `详细说明` |
| `交通费` | 날짜·통화·금액 | — | `详细说明`, (`出发地点`·`抵达地点`은 디디 등 전자영수증엔 ①, 지하철·버스 종이표엔 ③) |

**③으로 진짜 남는 건 두 종류뿐이다:**
1. **`就餐人`(같이 식사한 사람)·`同住人`(같이 묵은 사람)** — 사람 이름. 식당 영수증에 동석자가 찍히지 않고 호텔 인보이스에 룸메이트 이름이 없다. **사람이 기입할 때도 영수증이 아니라 기억으로 쓴다.**
2. **`详细说明`(상세 설명)** — 성격이 다르다. 값이 없는 게 아니라 **회사가 어떤 문장을 기대하는지 우리가 모르는 것**이다. 문구 규칙 한 줄만 정하면 ③ → ② 로 내려온다.

> **교훈 (2026-08-18)**: 처음에 영수증을 한 장도 안 본 채 "이 칸들은 영수증에 절대 안 나온다"고 단정했다가 사용자에게 지적받았다. **실물을 보기 전에 판독 한계를 단정하지 않는다.** 못 채운다고 말하려면 *어느 칸이 왜* 인지 위 3등급으로 갈라서 말한다.

## 7. 안 하기로 한 것 (스코프 경계)
- 화면 폼 자체를 흉내내거나 화면 기준으로 설계하지 않는다. **기준은 엑셀 템플릿이다.**
- 사내망 자동 로그인·자동 업로드는 v1 범위 밖 (최종 목표로만 유지).
- 손에 없는 템플릿(물품 구매 등)을 상상해서 설계하지 않는다.
- **모르는 값을 지어내지 않는다.** 정산은 회계 문서다. 근거 없는 값 대신 비워두고 물어본다. (CLAUDE.md 핵심 원칙 3)
